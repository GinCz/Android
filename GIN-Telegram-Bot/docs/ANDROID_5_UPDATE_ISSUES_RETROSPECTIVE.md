# 📊 Ретроспектива ошибок обновления и синтаксического анализа пакета на Android 5.1 (Alps MT6580, DOOGEE X3)

> **Автор:** Владимир Буланцев (@GinCz) & AI Engineering Standard  
> **Проект:** GIN-Telegram-Bot (`com.gincz.telegrambot`)  
> **Целевое устройство:** № 08 в реестре (DOOGEE X3, Android 5.1 Lollipop, API 22, 32-bit ARMv7, Alps MediaTek MT6580)  
> **Дата составления:** 2026-11-28

---

## 🎯 Введение и постановка проблемы

При попытке обновления приложения `GIN-Telegram-Bot` на смартфоне DOOGEE X3 (устройство 08, Android 5.1 Lollipop) как через встроенную кнопку интерфейса «Обновить», так и при попытках установки скачанных APK, система Android выдавала ошибку:
> **«Синтаксическая ошибка. Ошибка при синтаксическом анализе пакета»** (`INSTALL_PARSE_FAILED`).

В данном документе сведен полный детальный технический анализ всех выпущенных версий, выявленных первопричин, проведенных изменений, а также зафиксировано, что именно помогло, что не помогло и почему, с четким планом дальнейших действий.

## 🔍 Детальный разбор по каждой версии

### 1. Версия v002 (Первоначально установленная рабочая версия)
* **Что было реализовано:** Полноценный функционал SMS/Push шлюза, плюс модуль `UpdateManager` и кнопка `VladiMIR+AI ||| v002` для проверки и скачивания обновлений с серверов `gincz.com` и `eco-seo.cz`.
* **Архитектурная ошибка в коде:** Загрузка скачиваемого APK выполнялась в приватный каталог приложения:
  ```java
  File updatesDir = new File(activity.getCacheDir(), "updates");
  // Путь: /data/data/com.gincz.telegrambot/cache/updates/GIN-Telegram-Bot_vXXX.apk
  ```
* **Почему произошел сбой:** Каталог `/data/data/com.gincz.telegrambot/` на уровне Linux имеет права `0700` (`drwx------`) и принадлежит исключительно UID приложения (`u0_a...`). Системный установщик `com.android.packageinstaller` запускается под UID `system` (1000). При попытке установщика открыть переданный через Intent URI `file:///data/data/...` ядро возвращает отказ `EACCES (Permission Denied)`. На Android 5.1 это приводит к отображению модального окна: *«Синтаксическая ошибка. Ошибка при синтаксическом анализе пакета»*.
* **Критический вывод:** Код загрузчика v002 физически выполняется в оперативной памяти телефона. Какой бы идеальный APK ни находился на сервере обновлений, **нажатие кнопки «Обновить» в интерфейсе v002 всегда будет завершаться ошибкой доступа**.

---

### 2. Версия v004 (Интерфейс, безопасность токена и фирменные иконки)
* **Что менялось:** Защита Telegram Bot Token модальным окном изменения, увеличение шрифтов UI до 16–24sp, брендовые иконки Telegram в каталогах `mipmap-*`.
* **Что пошло не так:**
  1. *При обновлении через кнопку в v002:* Срабатывал старый загрузчик v002 (ошибка доступа к `/data/data/`).
  2. *При попытке прямой установки APK:* Парсер пакетов Android 5.1 аварийно завершался. Причина: создание каталога `mipmap-anydpi-v26` с адаптивными векторными XML-иконками `<adaptive-icon>` (поддерживаются только начиная с Android 8.0, API 26) и добавление в манифест атрибута `android:roundIcon` (появился в Android 7.1, API 25). На кастомных прошивках MediaTek MT6580 (Alps) системный `PackageParser` падал с исключением `InflateException: invalid drawable tag adaptive-icon`.

---

### 3. Версия v005 (Попытка исправления путей кэша)
* **Что менялось:** В `UpdateManager.java` каталог загрузки обновлений перенесен в `activity.getExternalCacheDir()` (`/storage/emulated/0/Android/data/.../cache/updates/`) с вызовом `apkFile.setReadable(true, false)` и `updatesDir.setExecutable(true, false)`.
* **Что помогло / что не помогло:**
  - *Что помогло:* Кодовая база получила правильную архитектуру загрузки для будущих версий.
  - *Что НЕ помогло:*
    1. На телефоне по-прежнему крутился старый скомпилированный код v002, который продолжал скачивать во внутренний изолированный кэш.
    2. Сам файл `GIN-Telegram-Bot_v005.apk` все еще содержал атрибут `roundIcon` и адаптивные иконки, из-за чего прямая установка APK также завершалась синтаксической ошибкой.

---

### 4. Версия v006 (Удаление roundIcon, адаптивных иконок и очистка META-INF)
* **Что менялось:**
  - Удален атрибут `android:roundIcon`.
  - Удален каталог `mipmap-anydpi-v26`. Приложение переведено на прямые растровые PNG во всех разрешениях (`mdpi`..`xxxhdpi`).
  - Из `META-INF/` исключены неподписанные файлы Gradle (`app-metadata.properties`, `version-control-info.textproto`), нарушавшие проверку `StrictJarFile` на Android 5.1.
  - Зафиксированы подписи Scheme v1 (JAR) и Scheme v2. `targetSdk` стабилизирован на 33.
* **Что помогло / что не помогло:**
  - *Что помогло:* Полностью устранены ошибки инфлейта иконок и проверки манифеста.
  - *Что НЕ помогло:* Прямая установка `v006.apk` на DOOGEE X3 всё равно выдавала «Синтаксическая ошибка».
  - *Глубинная причина (Smoking Gun):* В сборке v006 были включены параметры:
    ```kotlin
    isMinifyEnabled = true
    isShrinkResources = true
    ```
    Современный AGP 8.7 Resource Shrinker при сжатии вырезал неиспользуемые ID и оставил в скомпилированном бинарном файле `resources.arsc` пустые блоки:
    ```text
    INVALID TYPE CONFIG FOR RESOURCE 0x7f010002
    INVALID TYPE CONFIG FOR RESOURCE 0x7f050001
    INVALID TYPE CONFIG FOR RESOURCE 0x7f05000d
    ```
    В отличие от современных версий Android, нативный C++ загрузчик `AssetManager::addAssetPath` в Android 5.1 Lollipop не поддерживает пустые дыры типов и возвращает нулевой дескриптор ошибки при открытии APK. `PackageParser` не мог прочесть ресурсы приложения и аварийно завершал установку с кодом `INSTALL_PARSE_FAILED`.

---

### 5. Версия v007 (Полное решение совместимости на уровне движка ресурсов и байткода)
* **Что менялось:**
  1. **Отключен Resource Shrinker и R8 Minify:**
     ```kotlin
     buildTypes {
         release {
             isMinifyEnabled = false
             isShrinkResources = false
         }
     }
     ```
     После перекомпиляции проверка через `aapt dump --values resources` подтвердила: **ZERO INVALID CONFIGS** (таблица ресурсов абсолютно монолитна и непрерывна, аналогично работающему `GIN-SMS-Backup`).
  2. **Стабилизация Java байткода:** `compileOptions` переведены на `JavaVersion.VERSION_1_8` для совместимости с первой версией виртуальной машины ART.
  3. **Очистка gradle.properties:** Удалены устаревшие/депрекейтнутые параметры `android.enableR8` и `android.enableR8.fullMode`.
  4. **Выравнивание и подпись:** Удалены неподписанные файлы Gradle из `META-INF`, выполнено 4-байтное выравнивание `zipalign -f -v 4`, наложена чистая подпись схемы v1 + v2 (`apksigner verify: Verifies = true, 0 warnings`).
* **Что помогло:** APK стал на 100% валидным для Android 5.1.
* **Ограничение:** Обновить телефон со старой v002 нажатием кнопки «Обновить» изнутри приложения по-прежнему невозможно из-за бага загрузчика v002. Требуется единоразовая установка извне.

## 🚀 Чеклист для разработчика: Что делать дальше

Чтобы ни при каких обстоятельствах не сломать совместимость с Android 5.1 (DOOGEE X3 и аналогичные старые устройства):

1. **Никогда не включать `isShrinkResources = true` для проектов с поддержкой Android 5.0/5.1** в Android Gradle Plugin 8.x:
   Современный сжиматель ресурсов AGP 8 несовместим со старым парсером `AssetManager` на Android Lollipop.
2. **Всегда фиксировать `compileOptions` на Java 1.8:**
   ```kotlin
   compileOptions {
       sourceCompatibility = JavaVersion.VERSION_1_8
       targetCompatibility = JavaVersion.VERSION_1_8
   }
   ```
3. **Использовать исключительно растровые PNG-иконки** без адаптивных XML-иконок (`<adaptive-icon>`) и без атрибута `android:roundIcon` в `AndroidManifest.xml`.
4. **Всегда выполнять `zipalign -v 4` и подписывать схемами v1 (JAR) + v2:**
   Android 5.1 требует обязательного наличия подписи v1 и выравнивания неупакованных ресурсов.
5. **Для перевода устройства 08 на исправленный движок обновлений:**
   Выполнить однократную установку актуальной версии (v007/v008) через ADB на ПК Владимира:
   ```cmd
   D:\AI\tools\platform-tools\adb.exe -s S260C1ZS67024425 install -r "D:\MEGA\DOCS\desktop\GIN-Telegram-Bot_v007.apk"
   ```
   *После этого модуль `UpdateManager` будет работать из внешнего кэша, и все последующие обновления будут устанавливаться в один клик по кнопке прямо на телефоне.*
